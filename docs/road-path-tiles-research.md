## 0. TL;DR

- **当前道路是「完整 16px 满格地形」**：每个 R 格整格填 `cRoad` 土色，连续道路是一条 16px 实心土路带（实测单格内道路色列数 6~16，均值 ~11-15，边缘被 seam 摆动吃成锯齿）。用户「太粗」的根因 = **满格 + 替换基底 + 摆动边缘 + 单一固定土色**，四个问题叠加（P1~P4）。
- **推荐方案 = Option A「窄小径带 + 保存基底」**：grid 仍存 `R`（统计/图鉴/盖章逻辑零改动），但渲染时把 R 画成一条 **6px 心带 + 1px 深色描边**的窄路径，叠加在**盖章前保存的基底地形**上；道路色按基底**去饱和+压暗**自动生成（地形感知）。路径骨架用「过格心折线的距离场」直算（与现有 `distFor` 距离场机制同构），**恒定带宽、无 wob**。
- **为什么是 A 不是 B/C**：B（grid 存基底 + 独立路径叠加层）数据模型最干净但侵入大（统计/图鉴/河流盖章/签名缓存全改），而道路只占地图 1.1~1.8%；C（仅调色）不解决「太粗」。
- **实测硬约束**：道路 R 格的 8 邻签名在 main/tundra/volcano 全部唯一（15/15、15/15、22/22），**固定 bitmask 片集无法覆盖**；且多数道路贴海岸，按「邻居多数」推断基底会把**海洋**当基底（main/tundra 各 10/15 格）→ **基底必须在 stampLine 时额外保存**（仿 `heights` 先例，零新增成本）。
- 社区惯例：Stardew 路径放独立「Paths 叠加层」；DF 满格道路建构（货车需 3 格宽）；商业 16px 瓦片包用「路径片 + 路径↔草地过渡边片」做出窄观感；Rimworld「踩踏痕迹 = 基底的磨损变体」正是「地形感知道路色」的来源。

## 1. 当前方案诊断

### 1.1 现状（[事实，high]）

| 项 | 位置 | 说明 |
|---|---|---|
| R 定义 | `terrain.js:188` | `'R':{name:'道路', seed:13, elev:2, color:cRoad}`，独立地形 |
| cRoad | `terrain.js:23-29` | 暖棕土色 (186,140,88) + 横向车辙 `(y&3)` + 沙砾 hash |
| 铺路 | `mapgen.js:126-140` `stampLine` | 4-connected 线性插值，防对角间隙，**不覆盖 `~`**；`mapgen.js:75` 调用 |
| 过渡 | `tiles.js` | R 参与通用 seam 距离场过渡，与邻格任意配对 |
| 高度差 | `render.js:141-158` | R elev=2 参与 Phase 1 投影/唇边/崖壁 |

**git 历史**：`60a1c94` 引入（简单线性铺路 + 跨河木桥 `B`，cRoad=(170,156,124)）；`b6be58c2` 道路重做（4-connected + 防对角间隙 + 不覆盖水，cRoad 换成现在带车辙的版本，木桥代码由 `2491e3ff` 移除）——**道路从引入起就是完整 16px 满格瓦片**，重做只改了连通性/遇水终止，没改宽度。

### 1.2 问题清单（用户「太粗」的四条根因）

**P1. 16px 满格 → 视觉太粗 [事实，high]**
- 每张地图 R 格 15~23 个（占地图 1.14%~1.79%）：main 15、tundra 15、volcano 22、desert 23（实测 `genWorld` 统计）。
- 连续道路 = 一列/一行整格 `cRoad`，16px 宽实心带；基底地形（草地/苔原等）被整格抹掉。

**P2. 满格替换基底 → 无「小径穿过原野」层次 [事实，high]**
- 道路下的草地/苔原/沙漠不显示，两侧基底与道路格之间只有 seam 过渡，读作「一条大土路」，而非「原野上踩出的小径」。

**P3. 边缘复用 terrain seam 摆动 → 道路边缘锯齿、带宽起伏 [事实，high]**
- R 格边缘用 `distFor` seam 的 `wob`（`util.js:13`，幅度实测 ±2~4px）+ band=2px 过渡。实测（主图横路格 (32,12)，R↔G 配对种子 28685）：
  - 该格顶部行被草地色吃掉：行 0 仅 **4 列** 道路色（其余为草），行 1 9 列，行 2 10 列，行 3 起才 16 列（`road-test3.mjs`）。
  - volcano 竖路格 (17,16) 底部行（9-15）西侧 3~4 列被吞（带宽 12~14）。
  - 单格内道路色列数范围 **6~16**（主图水平 R 格采样 8 个：min 10.1 / avg 11.1 / max 11.7 列，阈值 40）。
- 即「16px 实心带」实际是 **6~16px 起伏、边缘 ±3px 锯齿** 的不规则土带。对地形过渡 wob 是「自然海岸线」，对道路则是「歪斜土路」。

**P4. 单一固定土色 → 低对比基底上道路不可见 [事实，high]**
- `cRoad` 基色 (182,137,86) 与各基底基色的欧氏距离（实测 `baseColor` 4 采样平均）：**沙漠 d=43.2**、碎石坡 d=59.8、泥地 d=64.1、泥滩 d=65.6、苔原 d=74.1、岩石 d=81.8；草地 d=101.4、雪地 d=183.9。
- 沙漠图上道路与沙色几乎融为一体（desert 图 R 邻接沙漠 ×76，实测），且沙漠图上沙格边缘与道路色判定互相误判（基底格上最多 12 列被判为「道路色」）。

**P5. 拐角/端点占大量 R 格 → 满格方块让转弯/终止处观感差 [事实，medium]**
- 实测结构统计：main 直段 3 / 拐角 2 / 端点 8；tundra 2/3/10；volcano 3/**17**/2；desert 3/**16**/4；三岔、十字均为 0。
- 拐角 = 2 个相邻满格方块（32×32 实心 L），端点 = 道路在河岸/海边骤然收尾的整块土方。道路大量沿海岸/河流走（main/tundra 各约 10 个 R 格正交邻居为海洋）。

### 1.3 正向结论（避免误判）

- 铺路连通性（4-connected、防对角间隙、遇水终止）设计合理，重做后的 `stampLine` 无缺陷，不在本次问题范围。
- 签名缓存/图鉴/统计机制健全：R 作为普通地形完全兼容；改造后统计与盖章逻辑可**原样保留**。
- 道路只占地图 ~1.5%，是**高频视线焦点**但**低频改动点**——改造收益大、风险局部。

> 算法层（bitmask 16/47、Marching Squares 16、Wang、Dual Tilemap）对比见既有文档 `docs/transition-tiles-research.md`——本项目实测 R 格签名全部唯一、任意地形配对、多邻居交界，**固定片集不适用**，路径渲染应保持逐像素程序化。

### 2.2 关键启示

1. **路径应是「叠加」而非「替换」**（Stardew Paths 层；Rimworld 磨损）。基底地形应保留在路径下方 → 直接支持「窄路露两侧基底」。
2. **窄观感要么靠薄条、要么靠边缘过渡片**（商业包）。本项目程序化瓦片 → 用「过格心折线距离场」直接画薄条最自然，复用现有距离场哲学。
3. **路径色应是基底的变体**（Rimworld 磨损 / 雪地压实的雪 / 沙漠浅色）——单一固定土色在沙漠/苔原上不可读（实测 d≤74）。
4. 功能上路径常需要较宽（DF 3 格），但本项目道路纯装饰 → 可以窄。

## 4. 推荐方案：Option A「窄小径带 + 保存基底」

### 4.1 基底从哪来 → 盖章时额外保存（实测排除「邻居多数」）

- **结论**：在 `stampLine`（`mapgen.js:126-140`）把 `grid[y][x]='R'` 之前，把盖章前地形写入并行数组 `roadBase[y*w+x]=old`；`genWorld` 返回对象追加 `roadBase`（仿 `heights:hhField` 先例，`mapgen.js:94` 零新增计算成本）。
- **为什么不能靠邻居多数**：实测 4 张图 0 个 R 格「全正交 R」，但按「非 R 正交邻居多数」推断基底时，**main/tundra 各 10/15 个 R 格会把海洋 (~) 当基底**（路贴海岸走）；剔除水体后又是猜测（路的另一侧可能是泥地/灌木/雪岩）。盖章时保存是精确、免费、无分支的方案。
- 兜底：若 `roadBase` 缺失（旧缓存/外部调用），退回「非水体正交邻居多数」。

### 4.2 邻居解析：R 邻居在其它格中解析为基底

- `buildMapCache`（`render.js:129-131` `nbrs`）计算邻接时，把每个 `'R'` 邻居替换为其 `roadBase` 地形。
- 效果：**道路两侧的基底（如草地）与被道路覆盖的基底是同材质 → 无缝连续**，草地在道路带两侧自然流动（解决 P2）；且邻 R 的草地格不再含 `R` 签名 → 归入普通草地格的缓存条目（消除「带 R 邻居」这一高熵签名带来的缓存碎片）。
- 水体邻居（如沿海路西侧是 `~`）保持为水体 → 基底格仍渲染出自然的沙滩/海岸过渡，窄路带叠在其上。

### 4.3 R 瓦片如何按邻接画窄条 → 过格心折线距离场

- R 格内，据**正交 R 邻居方向**（`nbs.n/s/w/e` 中哪些是 `R`）构造过格心 (8,8) 的骨架折线：
  - 1 个方向（端点）：竖直/水平短臂（路止于水边，带末端收圆帽）；
  - 2 个**对向**（直段）：过格心直线；
  - 2 个**相邻**（L 拐角）：两段折线在格心相接（实测拐点连续无空洞）；
  - 3 个（T 三岔）/ 4 个（十字）：相应多臂。
- 逐像素：`d = distToPolyline(px,py,skeleton)`；`d ≤ w/2` → 道路心色；`w/2 < d ≤ w/2+1` → 深色描边；否则 → 基底像素（见 4.2）。
- **带宽恒定、无 wob** → 消除 P3。像素级实测（`road-test5.mjs`，骨架折线距离场）：
  - 6px 直线竖 `....+######+....`（38% 格宽、96/256 像素），L 拐角 95 像素且拐点 (8,8) 连续，T/十字 156 像素；
  - 4px（25%）同样连续，但低缩放（zoom≤0.6）下仅 ~2-3 屏幕像素，偏细。
- 这与现有 `tiles.js:45-61` `distFor`「到边界距离场」是同一机制，只是把「缝线」换成「路径骨架」，**架构同构、易复用**。

### 4.4 地形感知道路色（解决 P4）→ 基底去饱和+压暗，按亮度掺土色

- 公式：`roadColor(base) = mix( desat(base, 45%) * 0.88, cRoad, clamp(1 - L*1.2, 0, 0.55) )`，其中 `L`=base 相对亮度。
- 效果（实测 `road-test6.mjs`，道路色 vs 基底对比度）：
  - 草地 → (128,129,82) 土橄榄（d=54，读作踩出的土径）；
  - 雪地 → (197,201,206) 浅灰**压实雪**（d=50，符合「雪地小径=压实的雪」）；
  - 沙漠 → (165,145,114) 奶油淡沙（d=38，比现 cRoad d=43 稍好，主要靠描边定型）；
  - 泥地 → (147,112,76)（d=28）、苔原 → (136,121,93)（d=29）：本就是土/苔，磨损痕迹自然。
- 自动覆盖 26 种基底，无需逐对维护调色表；若追求精确可再覆写少数基底（E/W）的显式值。
- **1px 深色描边**（基底/路心压暗 ~40%）是低对比基底（沙漠 d=38、碎石 d=15）上路径「弹出来」的关键，建议必配。

### 4.5 与签名缓存 / 过渡 / 图鉴 / 统计共存

- **签名缓存**（`tiles.js:120-195`）：非 R 格用「R→基底 解析后的邻居」签名（共享度上升）；R 格走新 key `'R'+base+8邻签名`（base 独立于签名，因沿海时 base 不在签名中——实测）。缓存的是「抖动前模板」的既有机制不变。
- **过渡**：R 不再作为 seam 过渡参与方（它是覆盖层）；其它地形对的过渡完全不受影响。
- **图鉴**（`palette.js`）：`PALETTE_ORDER` 中 R 保留（26 种不变）；`pairs4` 中 `['R','G']` 片改为「草地基底 + 顶部窄路带」示意（或标注为「窄路叠基底」），避免与现在「R↔G 满格过渡」语义冲突。
- **统计**（`main.js:46-49`）：grid 仍存 `R` → 「道路 N 格」照常，零改动。
- **盖章/河流/深渊**（`mapgen.js:67-91`）：grid 语义不变，`carveChasm` 的 `'R'` 跳过判断、河流终止等全部照旧。
- **高度差覆盖层**（`render.js:141-158`）：R elev=2 保留；可选微调：R 格的唇边/崖壁基色读 `roadBase` 而非 `cRoad`（1 行），使路的浮雕与基底一致。

### 4.7 验证方法

1. **Node 直调回归**（复用本次 `road-test*.mjs` 套路）：无过渡格逐字节不变；邻 R 的基底格 = 普通基底格（与「把 R 当基底」的渲染逐字节一致）；R 格为窄路新渲染。
2. **像素级断言**：道路带宽恒为 w、边缘无 wob；L/T/十字拐点连续；沙漠/雪地/草地上道路色对比度 d≥25。
3. **VLM/浏览器截图**：5 图 + 图鉴，重点看窄路清晰度、拐角、海岸路段（路贴水时的沙滩过渡与窄带叠加）。

## 5. 16px 内窄路可辨识度专项评估

- **6px 心带 + 1px 深边**（总视觉 ~8px）：直线/L/T/十字在 16px 格内实测全部清晰，拐点连续无空洞（`road-test5.mjs` ASCII 验证）；占格 38%，屏幕 6px（zoom 1）/ 3px（zoom 0.5）。
- **4px**：连续但占格 25%，低缩放变 2px，辨识度临界；不推荐为主宽度。
- **8px 以上**：占格 ≥50%，开始回归「满格粗带」观感，失去「窄小径」意义。
- **结论**：推荐 w=6px（范围 5~7px 可调），配 1px 深边；这是 16px 程序化瓦片下「窄而有存在感」的甜点值。**低对比基底（沙漠/泥地/碎石）的可读性主要靠描边，而非路心色**。
